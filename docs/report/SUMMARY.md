# 报表能力 · 总说明（2026-10-18）

> 给「以后回看这次改动的人」看的一份东西。
> ⚠ 详细的逐项证据在旁边的分报告里（`A1` / `A2` / `R1` / `R2`），
> 这份只讲**改了什么、为什么这么改、怎么验的、哪些没验**。

---

## 1 · 一句话

给**仪表盘的「调用统计」**补了一块**报表区**：
左边 **Top 账号榜**（带条形与占比）· 右边 **上游占比环**（`conic-gradient` 画的，**零图表库**），
再加上趋势的 **24h / 7d 范围切换**。

⚠ **没有引任何依赖**：环是 `conic-gradient`、条形是 `div` 宽度、
（既有的）趋势是内联 SVG —— 与这个项目一贯的"零图表库"立场一致。

---

## 2 · ⚠ 最重要的一条：**数据层原本就比我们以为的完整**

我一开始的判断是错的，而且是**两次**：

| 我早先的说法 | 实探结果 |
|---|---|
| 「只有 `by_model` 一个聚合维度」 | ❌ 错：`by_model` / `by_provider` / `by_uid` **三个都在** |
| 「缺 `daily` / `trend` / `series`」 | ❌ 错：`GET /admin/stats/series?range=24h\|7d` **一直就有**（返回 `ts/total/ok/fail/tokens` 桶） |

⚠ 两次都是**先派活/先下判断、后去实探**造成的。
⇒ 现在这两条已经**写进 `BRIEF.md`**，并且入账本（`E060`：先探接口再判断"缺什么"）。

## 3 · 实际改了什么

### 后端（`internal/admin/`）

| 改动 | 说明 |
|---|---|
| **`dimStat` + 三个 `*_detail`** | `by_model_detail` / `by_uid_detail` / `by_provider_detail`，每桶带 `req/ok/fail/tokens/tokens_raw/think_tokens/avg_ttfb_ms`。⚠ **旧字段一字未改**（`by_model` 的 int 映射、`by_provider` 的 `calls/ok/fail/credit`、顶层标量全部原样）—— 有单测守卫 |
| ⚠ **上游用 `provider` 字段，不用 `model` 前缀** | 实测：`model="-"` 的 2 行取不到前缀 ⇒ `workbuddy` 会少计 2 次、**成功率被算高**（99.96% vs 99.87%）。前缀法只作兜底 |
| ⚠ **tokens 两条口径并存** | `tokens` = **剔负**（与顶层同口径，明细求和 == 卡片总数）· `tokens_raw` = 原始和。⚠ 实测差 **4128**（日志里有 `tokens=-1` 的脏行） |
| ⚠ **`multTableCached` 首次同步建** | 修一个**我自己先前引入的回归**：原来表为 nil 时也丢后台 ⇒ **首次请求拿到空倍率表** ⇒ 两个单测直接红。现在"表为空 ⇒ 同步建一次；表过期但非空 ⇒ 才丢后台" |
| ⚠ **启动预热**（`admin.New` 末尾） | `/admin/stats` 首屏实测 **4.6 秒**（冷 IO：读 28000 行 + 首次解析）。预热把 `statsItems()` 先跑一遍。⚠ **效果待干净环境复测**（见 §6） |

### 前端（`internal/server/webui.html` —— ⚠ 单文件，由主脑独占）

| 改动 | 说明 |
|---|---|
| **报表区双栏** | `.duo` = `grid auto-fit minmax(320px,1fr)` ⇒ 宽屏两栏、窄屏自动退化成一列，**不用写媒体查询** |
| **`renderStatsReport(s)`** | 画 Top 榜（`div` 宽度条形 + 值 + 占比）与环（`conic-gradient` + **带值图例** + 环心写总量与口径） |
| ⚠ **位置：放在 `renderStats` 的**开头**（`if (!s) return;` 之后）** | ⚠ 不能放末尾 —— 函数体里有一处 **`return [`（提前返回卡片数组）**，插在它之后就是**死代码**（我踩过：面板全空而 `pageerror` 干净） |
| ⚠ **`calls()` 同时认两种形状** | `{calls,ok,…}` 与裸数字。⚠ 只认一种会**静默出 0**（环形图整块不画，而控制台无错） |
| **趋势范围切换** `24h` / `7d` | 复用已有 `.tog` 样式，照 `growthView` 那处的写法（`dataset` 判等 + `toggle('on')`）。⚠ digest 里**带上 range**，否则切换时末尾桶若相同会被判"没变"而不重绘 |
| ⚠ **文案不撒谎** | 趋势说明行原来写死「最近 24h 逐小时」，切 7d 后就是**假话** ⇒ 现在跟着 `trendRange` 变 |

## 4 · 怎么验的（三层交叉）

```
① 独立算法（Python 直读日志，A2 的 tools/verify_stats.py）
      uid Top1 = 260825100642697603 = **1160**
② 接口聚合（A 的 by_uid_detail）        = **1160**     ✓ 一致
③ 前端画出来的（Top 榜第一行）          = **1160**     ✓ 一致
④ 另一条独立线索：A2 说 provider 字段给 workbuddy = **2299**（前缀法只会给 2297）
      接口 + 图例都给 **2299**                          ✓ 一致 ⇒ 说明确实用了 provider 字段
```

* A1 的**独立核对**：冻结日志后 **551 条断言 0 失败**（66 桶 × 7 字段）· **变异验证 2 处都报红**（证明测试非空转）
* 我的验证：`node --check` 0 错 · `go build ./...` = 0 · 单测全过 · ⚠ **每次都看图**
* 表结构复核：20 张可见表逐个打印"可见/被藏的表头"（⚠ 不靠看一张图）

## 5 · ⚠ 哪些**没验**

* **P2「缓存聚合产物」没做** —— 见 §6，那需要深拷贝（调用方会就地改那个 map）。
* **7d 桶的边界**（区间首尾那两天）没专门核。
* **空日志 / 极端脏数据**下报表区长什么样没实测（R2 正在攻击这一面）。
* **`tokens=-1` 的成因**没查明（只确认了存在 4128 行）。
* **R1 / R2 两个复核报告**在写这份时还没出 —— 它们可能推翻上面某一条，⚠ **以它们的结论为准**。

## 6 · ⚠ 一个必须说清的测量陷阱

`/admin/stats` 冷启动我测了三次：**4634ms · 3078ms · 3507ms**（波动 1.5 秒）。
同一批单测：**5.2s · 8.2s · 2.8s**。

⚠ 原因：**当时有两个复核代理在跑**（它们各自起 7864 + Playwright）。
⇒ ⚠ **所以"预热把首屏降了 34%"这个说法我**收回**了** —— 波动比效应大，单次测量不足以下结论。
⇒ ✅ **正确做法**：**环境干净时多次测取中位数**。已入账本（`E058`）。
