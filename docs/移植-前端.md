## 零、能力重合度判定（这一步先做掉 70% 的无效项）

### 0.1 两个前端不是一个物种

| 维度 | hyxapi | workbuddy2api | 结论 |
|---|---|---|---|
| 构建 | Rsbuild + TS + Tailwind 4 | **无构建**，Go go:embed 一个 html | **框架/工具链不可移植** |
| 页面 | 用户端 + 管理端 + 模型定价 + 充值 + 工单 | **10 个区块**：dashboard channels groups apikeys accounts jobs logs models chat settings | 多租户页面**全部不需要** |
| 测试 | 68 个 node:test **纯逻辑**测试 + Storybook | tests/frontend 门禁（语法扫描）+ CDP 截图 | 两者互补，各有缺口 |

### 0.2 ⭐ 最重要的好消息：**hyxapi 没有第三方 UI 组件库**

package.json 依赖清单里**没有** antd / semi / radix / shadcn / mui —— **34 个 components/ui/* 全部手写**（结构 + Tailwind class 一体）。

⇒ 所以「能不能只抄 CSS 不抄组件」这个问题**不成立**：这里本来就只有手写组件，**结构与样式可以直接去框架化搬运**。
⇒ **真正的框架绑定只有 4 处**：React 运行时 / TanStack Query / zod / i18next。

唯一外部 UI 依赖是图标 `lucide-react`（零依赖 SVG 集）—— 翻成内联 SVG 即可，不构成障碍。

## 四、⚠️ 图表对比（你最该看的反向结论）

hyxapi **没有** echarts / recharts / visx / d3 / chart.js —— 全部手写 SVG（2 处）+ 1 处**用 div 画柱**。

| 维度 | 你的 dash-chart.js（332 行 / 8 函数） | 它的 SpendingTrendChart.tsx（97 行） | 谁更好 |
|---|---|---|---|
| 共享方式 | **8 个函数抽成共享层** | 单文件，未抽 | **★ 你胜** |
| 数值防御 | `dcNum`（NaN 进 SVG 属性会变 x="NaN"，浏览器**静默丢弃**） | 无统一防御 | **★ 你胜** |
| 双 Y 轴 / 柱状图 | 支持 | 不支持 / 用 div 画柱 | **★ 你胜** |
| 十字准线 + 底带 | `dcCursor + dcBand` | 只有十字线、无底带 | **★ 你胜** |
| **曲线平滑** | 折线（无平滑） | **贝塞尔 + 0.36 手柄** | hyxapi 胜 |
| **轴标签精度** | 固定 toFixed | **按量级自适应 + Intl 本地化** | hyxapi 胜 |
| **响应式** | 固定 W | **ResizeObserver 自适应 viewBox** | hyxapi 胜 |
| **键盘 / 无障碍** | **无** | ArrowLeft/Right/Home/End/Escape + **sr-only 数据表** + aria-describedby | **★ hyxapi 压倒性胜** |

**结论：你的共享层方向是对的，只需补 3 个函数**（F8）。
⚠️ **不要抄**它用 div 画柱状图那处（PerformancePanel.tsx:29-32）—— 靠 flex 撑宽，数据点一多就挤成 1px，且没有轴/刻度/tooltip 定位。

## 七、一句话对比

**后端**：hyxapi 领先很多（协议转换 26K 行、审计、状态机），你有 **C1/C2 两个大动作**可选。
**前端**：hyxapi 只领先**几个纯逻辑内核**；你的单文件控制台在 UI 基元上**并不缺**，甚至在**列设置、拖拽列宽、图表共享层、轮询省流**四项上**明显强于它**。

⇒ **前端别做大规模迁移。** 先做 F1（功能性问题）+ G1/G2（治你那个已知事故），再按批次消化。
