## 1.5 真正值得移植的（按价值排序）

### ① setup 端点的**语义分离**（0.25 天，中价值）

**它做对的**：把「初始化」与「注册」分成两件事。
. `/api/setup` 只在**系统未初始化**时可用，建 root（100）
. `/api/user/register` 建普通用户（1），与初始化无关
. 于是「系统初始化」有**独立的存在形式与查询接口**（`GET /api/setup` 回 `Status`/`RootInit`/`DatabaseType`）

**你的**：两者合并，用 `Count()==0` 隐式判断 —— 在**单账号场景下其实更简洁**（少一个状态、少一张表、少一类竞态）。
但缺一件事：**前端无法在登录前问出「这个部署初始化了吗」**，只能去试 `register` 撞 403。

⇒ **建议**：不加 `/api/setup`，但**加一个只读的 `GET /api/bootstrap`**（或复用现有 `/status`）：
```json
{ "initialized": false, "account_count": 0, "register_open": true }
```
⇒ 前端登录页据此决定**显示「创建管理员」还是「登录」**，而不是让用户先撞一次 403。

证据：`controller/setup.go:25-50` 的 `GetSetup` 就是干这个的。

### ② ⭐ **启动自愈：从证据推导标记**（0.5 天，高价值）

**它的逻辑**（`model/main.go:57-82`）：

```
读 setup 表
  ├─ 无记录 且 root 用户存在  → 补建记录，Setup = true   ★ 自愈
  ├─ 无记录 且 无 root 用户    → Setup = false           （正常首启）
  └─ 有记录                    → Setup = true
```

**为什么值得抄**：你的「已初始化」标记**完全依赖 `data/accounts.json` 的内容**。若
. 用户手工清空/损坏了这个文件 → 库看起来是空的
. 从备份恢复时**只恢复了后半段**
. 文件权限问题导致解析失败

⇒ 「已初始化」的**证据链就断了**，而管理员可能还在别处有痕迹（比如 `data/sessions.json` 里还有他的会话）。

**具体建议**：给 `internal/account` 加 `InitializedEvidence()`，**从多个地方找证据**：

```
证据 1：accounts.json 里存在 IsAdminRole 的账号          → 已初始化
证据 2：sessions.json 里有属于某个 user_id 的有效会话   → 已初始化（印证人存在过）
⇒ 两者皆无 ⇒ 未初始化（走 bootstrap）
⇒ 有证据但账号文件里没有管理员 ⇒ ⚠ **不要静默放开 bootstrap**，而是：
     · 拒绝 bootstrap（防「删一个文件就能重拿管理员」这条提权路径）
     · 同时在日志与 /status 里明确报「检测到历史痕迹但账号已丢失，请从备份恢复」
```

⚠️ 最后那条**是安全关键**：hyxapi 的 `CheckSetup` 在「有 root 才补标记」的方向上安全，但**反向不设防** —— 照搬「无记录就允许初始化」就打开了「删文件 → 重拿管理员」。
你在 `store.go:51-53` 已有同类判断（「解析失败返回错误、**不静默重建**」），这条是它的延伸。

### ③ 跨进程互斥（0.5 天，中高价值，**取决于是否多进程部署**）

**它的做法**（`model/setup.go:20-21, 33-68`）：

```go
// Keep the administrator, site address, mode options and completion marker in one commit.
// ID 1 also fences concurrent initializers in separate server processes.

DB.Transaction(func(tx) error {
  tx.Model(&Setup{}).Count(&completed)      // 读
  ...建 root...
  tx.Create(&Setup{ID: 1, ...})            // ★ 写死主键 1 ⇒ 第二个进程撞主键失败
})
```

**关键**：把「检查」与「写完成标记」放进**同一事务**，用**写死的主键**当锁 ⇒ **跨进程**也只有一个能成功。

**你的**：`sync.Mutex` + `len(s.users) > 0` + 写文件。**同进程内安全**。

**风险场景**：
. 同时开两个进程指向同一个 `data/` 目录（调试时忘了关旧的）
. 将来上多副本
⇒ 两个进程各自 `s.users` 都是空的 ⇒ **两个都建出管理员**，而 `accounts.json` 后写的覆盖先写的 ⇒ **一个管理员凭空消失，日志里没有任何线索**

**具体建议**（不引数据库也能做到）：

```
CreateBootstrap 里，锁内写文件之前：
```

## 2.6 ⭐ 会话 cookie：它有一个你可能缺的细节（hint cookie）

### refresh cookie（`service/auth_session.go:289-308` + `common/session_cookie.go:47-67`）

### ⭐ hint cookie（`common/session_cookie.go:324-352`）

```
HttpOnly = false        ← 故意：JS 要能读（但读到的也只是 1）
值恒为 "1"              ← 不含任何信息
```

**它解决什么**（`:324-352` 有长注释）：控制台冷启动时前端**无法知道有没有登录态**，只能盲发一次 `/api/user/auth/refresh` ⇒ ① 没登录时会拿到**注定 401** 的响应；② 且**消耗限流预算**。
⇒ 用一个**不含信息**的旁路 cookie 当「登录态存在性」探针：有它才去 refresh，没有就直接渲染登录页。

**注释里那条纪律很关键**：
```
必须与 refresh cookie 同生共死
```
⇒ 任何删除/续期 refresh cookie 的地方，都必须同步处理 hint cookie，**否则探针会说谎**（说有登录态、实际 refresh 已失效 ⇒ 又回到盲发 401）。

**⚠️ 你的场景**：你已有 `internal/account/session.go`（17.6 KB）。前端冷启动是否有这个「盲目 401」问题**需要实测** —— 若你的登录页已是**服务端渲染时就知道登录态**（`webui.go` 注入），那你**没有**这个问题，**跳过**。
⇒ 判定：**先观察，别急着抄**。若控制台有「打开页面先闪一下登录页再跳回」的现象，那就是它。

**另外 `Path = /api/user/auth` 那条**：把 cookie 作用域缩到只在该前缀下 ⇒ 其它路径的请求都不带这个 cookie（减小泄露面，也让「误把 refresh token 记进日志/转发给上游」的概率下降）。**这条可直接照抄思路**，成本很低。

## 3.6 ⚠️ 前端实现前的额外约束（来自 AGENTS.md）

**若要重写，amis 的表格规范与你的诉求吻合**（飞书/钉钉式固定行高 + 横向滚动 + 紧凑），但要先确认 amis JSON schema 能否表达你现有的**列设置**（`COLS` 23 处）与**拖拽列宽**（22 处）——**这两项 hyxapi 都没有，是你的独有资产**。

### 4.1.4 ⚠️ ④ 那组的「结构性不适用」怎么处理（这是本主题最需要裁决的一点）

hyxapi 的「依赖健康」是**它自己有这些依赖**才成立的：
```
主数据库   6 指标：活跃 / 空闲 / 已打开 / 最大连接 1000 / 等待次数 / 等待耗时
           ← 来自 sql.DB.Stats()，只有 GORM + SQL 连接池才有
日志数据库 同构（它还支持把日志拆到独立库）

           ← 只有「有 Redis 但没开」这个状态才存在
```

**我方真实依赖**（要换成这些才有意义）：
```
① data/*.json 文件（accounts / sessions / state / apikeys）
   → 可报：文件大小 / 最后写入时间 / 是否解析成功 / 写入是否失败过（你有 saveOrLog 的日志）
② 账号池（internal/pool）
   → 可报：健康号数 / 冷却中 / 熔断中 / 自动禁用 / 在途 inFlight
③ 上游 provider（11 个）
   → 可报：每个上游的 provState（熔断中？TTFB EMA？）
④ 缓存（我方有缓存四格 + 趋势图）
   → 已有
⑤ 后台任务（internal/tasks? / schedule）
   → 可报：正在跑的任务 / 上次运行时间 / 下次触发
```

⇒ **不是「照抄它的 6 个指标」，而是「照抄它的『依赖健康』这个栏目位置与形态，内容换成我方真实的依赖」**。
