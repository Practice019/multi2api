# 前端重复模式实测与结论（T-340）

结论：**不抽**。理由与数据如下；将来要抽的前提也写在最后。

## 一、实测数据（`internal/server/webui.html`，16807 行）

| 指标 | 数量 | 说明 |
|---|---|---|
| `innerHTML =` | 129 处 | **不是**重复指标 —— 它们是不同面板各自的渲染，结构并不相同 |
| `toast(` | 99 处 | 已在用一个共享函数（这本身就是"已抽过"的形态） |
| `await admin(` | 60 处 | 同一个 API 封装（已抽过） |
| `class="accttable"` | 23 行 | ★ 逐条看过后：**真正的同构渲染块只有 2 处**（L9789、L9968 的 `host.innerHTML = head + \`<table class="accttable">…\``），其余是静态 HTML 里的 3 处表格标签与 CSS/注释引用 |

⇒ 「129 处 innerHTML」里**结构性相同**的只有约 **2 处**，可抽取的收益 ≈ 20~40 行。

## 二、为什么仍然不抽

1. **收益小**：真实重复 ~2 处、约 20~40 行，而该文件 16807 行。
2. **风险大且可见**：这一层是"取数 → 拼 HTML → 塞 innerHTML"，改错的表现是**页面白屏/错位**，
   而不是测试变红。
3. **代价可避免**：`accttable` 的样式与列语义已经由 **`internal/server/theme-max.css`（唯一真相）**
   统一 —— 也就是说视觉层早就共享了，剩下的只是两段渲染代码长得像。

## 三、将来要抽的前提（按序）

1. 先把"表格渲染"提成前端的一个 **render 函数**（`renderAccountTable(rows, cols)`），
   并让**至少两个**调用点切过去 —— 一次只切一处，每切一处跑一遍回归。
2. 改完必须：
   - `node tools/theme_sync.js --check`（视觉层同步没被破坏）
   - `node tests/frontend/run_frontend_suites.js`
   - 关键路径 e2e：`node tests/frontend/accounts_e2e.js` 等（本仓 `tests/frontend/` 下有 **152 个** e2e 脚本，
     另有 **17 个** webui 相关 Go 测试）
3. 任何"前端没有测试兜底"的说法都是**错的**（T-340 实测）：兜底是有的，
   但它是**端到端**的 —— 所以改动要小步、每步都跑一遍。

## 四、附：这条结论纠正过一次
