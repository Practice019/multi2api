## 1. 已确认的产品契约

- C-01：外部统一为 New API 式设施：渠道、路由组、令牌、公开模型；不照搬商业计费体系。
- C-02：标准渠道提供 URL＋Key＋显式获取模型能力；内置渠道提供上游登录／导入及多账号能力。
- C-03：默认一个内置上游对应一条渠道、多个账号；账号池成为该渠道内部凭据能力，不再与渠道平行暴露为两种选路体系。
- C-04：保留内置上游续期、签到、额度查询及冷却能力；OAuth 凭据不伪装成普通 Key。
- C-05：分组是路由组，渠道加入组、令牌选择组；令牌模型白名单与组可用模型求交，额外收窄权限。
- C-06：公开模型可同时由标准渠道与内置渠道提供；渠道映射方向为公开模型名→真实上游模型名。
- C-07：客户端使用公开模型名，无需 provider 前缀；保留旧前缀名的兼容映射，不误合并不同模型。
- C-08：请求链统一为令牌→组→公开模型→渠道→Key／账号→执行，不能保留绕过组授权的旧旁路。
- C-09：渠道层纯轮询，不使用 priority/weight；内部可用 Key／账号也纯轮询，跳过 disabled/cooling/unavailable。
- C-10：失败确需重试时进入下一候选，单请求不重复使用同一资源，有重试上限；只保留窄策略接缝。
- C-11：旧权限迁移不得放大；旧模型集合组不能按名称直接变为新资源范围组。
上述均已确认，不再列为“是否采用”的待裁决项；技术细节仍按 §4 冻结，不冒充用户已确认。

## 3. 现状差异、目标实体与接缝

历史现状：channels SQL、tokens SQL、groups JSON 和 Pool 分处不同存储／资源体系。
历史组是模型集合＋别名，组并集覆盖旧白名单；目标是资源路由范围与令牌白名单交集。
历史渠道转发存在 DefaultGroup 固定入口，渠道权重随机；目标统一组候选与两层纯轮询。
历史目录有 SQL／内存分支、刷新计数与明细分离、账号记录数代替可调用状态等风险。
这些是报告基线差异，实施前按本次 HEAD 定向重验，不把历史行号当新实现真相。

| 目标实体 | 职责与关系 | 真源与派生边界 |
|---|---|---|
| Channel | 稳定非秘密 ID、类型、启停、组成员关系、公开→真实映射、支持端点 | 接入配置为真源；禁止以 Key 或 OAuth token 当实体 ID |
| BuiltinBinding | 内置渠道关联 provider ID 与现有账号来源 | 凭据内容仍封装在上游；一上游一渠道，来源映射可追溯 |
| CredentialRef | 渠道内 Key／账号的稳定非秘密引用及资格状态 | 账号生命周期沿现有能力；不复制 OAuth 为静态 Key |
| RoutingGroup | 稳定组 ID 与渠道集合 | 模型可服务集合由渠道映射和能力派生，不另建可独立改写的能力事实源 |
| PublicModel | 公共名称、端点能力、提供渠道及目录来源 | 同名合并必须有显式映射与语义确认；不同模型不靠模糊名称自动合并 |
| TokenPolicy | 稳定非秘密令牌 ID、选组、模型约束、IP、期限和额度 | 与 SQL 及运行索引一致；秘密只用于认证，不能充当管理引用 |

目标数据流：认证与额度/IP校验→解析选组→规范化公开名→计算组候选与模型交集→协议资格过滤→渠道 RR→内部凭据 RR→执行。
目录流：渠道显式模型获取／已知能力→版本化目录快照→组范围目录→令牌白名单过滤→`/v1/models` 与生效预览。
接缝 S-01：渠道适配描述支持端点、模型发现及执行能力；标准与内置适配返回统一结果，不泄露 Secret。
接缝 S-02：凭据枚举／原子选择／资格反馈；续期、签到、额度和冷却由内置实现保留，路由只认中立资格。
接缝 S-03：候选解析与授权计算共用规则；目录、预览与执行不能各写一套组／模型权限判断。
接缝 S-04：窄选择器只处理合格稳定 ID 集合、RR 游标及请求排除集；不内置具体上游或复杂策略。
接缝 S-05：执行结果明确未输出／已输出、可重试类别及资源反馈；错误分类继续通过 gateway 中立契约表达。

## 4. 实施前技术冻结项（建议默认，尚非用户已确认细节）

| 编号 | 建议默认 | 必须冻结与验收 |
|---|---|---|
| F-01 多组 | 所选组渠道候选并集、按稳定 ID 去重；一个共享渠道只出现一次，不隐含组顺序优先级 | 相同候选集合共用轮询作用域；改变组顺序不改变候选或优先级 |
| F-02 渠道 RR 作用域 | 单进程内按候选集合身份＋公开模型＋端点类别共享游标，不按令牌建立隐式偏好 | 原子选择与递增；多实例暂不保证全局 RR，部署范围在切换前确认 |
| F-03 内部 RR | 每渠道＋模型／端点资格范围独立游标；候选按稳定资源 ID 排序，不按秘密排序 | 明确不可用跳过、预约与释放、并发在途容量，不能把纯 RR 理解成忽略可用性 |
| F-04 集合变化 | 游标保存上次稳定 ID，变化后取排序后继，删除锚点取其后继，绕回最小 ID；重启从首项开始 | A/B/C、动态增删、冷却恢复、全部不可用及并发序列有确定断言 |
| F-05 尝试与重试 | 建议总执行次数上限 3（含首次）；渠道先向下一条轮转，返回某渠道时再取未尝试内部资源 | 上限是技术建议待冻结；唯一资源标识纳入请求排除集，耗尽即停止，不空转 |
| F-06 重试类别 | 仅执行层明确标记的临时网络／限流／上游故障可重试；客户端错误、转换失败、取消和确定性终态不重试 | 超时且可能已受理的非幂等操作默认不重试；不能仅凭任意 5xx 重放所有协议 |
| F-07 输出边界 | 响应头／SSE 数据向客户端提交后禁止重放；取消立即停止后续选择 | 假流写出首事件后再失败，断言无第二次执行、无二次计费／重复内容 |
| F-08 跨渠道协议 | 仅在同一公开模型及同一请求端点语义兼容时换渠道；不存在转换契约即排除 | 同名不代表协议相同；chat/image/tool/stream 不支持时明确拒绝，不偷偷降级 |
| F-09 白名单空值 | 建议显式开关：未启用＝不额外收窄，启用且空集合＝拒绝全部；有效权限始终受组范围限制 | 旧 nil/空串/空数组须逐项映射；有组空集拒绝；新令牌无有效选组默认拒绝，不隐式全局组 |
| F-10 兼容名字 | 旧前缀先映射至稳定公开名，再按同一组与白名单准入；映射歧义拒绝并提示 | 同一资源不能借新旧名字重复尝试，兼容名不得成为授权旁路 |
| F-11 删除语义 | 建议删除最后可用组／渠道关联前要求重分配或阻止操作，不能自动变为不限 | 部分失败和并发删除按版本检查；实体删除不自动删除仍有其他提供者的公开模型 |
| F-12 安全与复制 | 建议只信显式代理；列表掩码、按需明文；已映射公开名可单行复制，批选资格仍独立 | 密钥披露、可信代理及合成行复制范围须冻结；复制不代表推理已验证 |

F-01～F-12 是实现前必须给出答案的技术契约，不引入新的复杂策略层；未冻结部分阻塞相应任务。
有效模型集合建议定义为“所选组可服务公开模型集合 ∩ 启用的令牌模型集合”；未启用约束只省略后一个交集项。
资源暂时冷却不应删除长期授权事实；目录分别显示配置可服务、当前可选和未知，不能把缓存状态当权限撤销。

### 阶段 A：冻结契约与权限基线

**U-01 契约冻结与最小接缝设计**
- 候选文件：`internal/gateway/provider.go` 与相关扩展文件、`internal/channelroute/route.go`、`internal/channelstore/`；先只读确认。
- 依赖：用户已确认 C-01～C-11；冻结 F-01～F-12，明确端点兼容、资源 ID、重试反馈及生命周期责任。
- 最小范围：定义 S-01～S-05 的行为与依赖方向，不预先重写全部 Provider，也不让核心导入具体上游。

**U-02 存量权限与来源 dry-run 基线**
- 候选文件：`internal/groupstore/`、`internal/apikey/sql.go`、`internal/store/token.go`、`internal/channelstore/` 的迁移接缝及测试。
- 依赖：U-01 的 ID、公开名和权限语义；可与统一适配实现并行，但不可修改同一存储文件。
- 最小范围：隔离夹具计算旧 token 有效模型、组来源、别名目标及 provider/channel/account 来源映射。
- 验收：输出非秘密差异清单，区分 unrestricted、restricted-empty 和确定模型集合；无法解析／歧义项阻塞迁移。
- 风险／回滚：动态目录无法证明完整旧权限时不能用当前快照冒充全集；保留版本化兼容规则或人工确认，不扩大权限。

阶段 A 门禁：技术契约冻结、旧权限比较器可信、歧义项可定位；历史报告的覆盖语义仅作为旧行为基线。

### 阶段 B：统一渠道适配与目录

**U-03 标准／内置渠道适配与装配**
- 候选文件：`internal/channelstore/`、`internal/gateway/`、`cmd/server/main.go`、`cmd/server/*creds.go`，现有具体上游能力按需定向修改。
- 依赖：U-01；标准适配与内置适配可在接口冻结、文件隔离后并行，由单一装配负责人合并。
- 最小范围：标准 URL＋Key；内置 provider 绑定现有多账号来源，保留登录／导入、续期签到额度冷却，不复制 Secret。
- 验收：fake OAuth 续期后同一 CredentialRef 仍可用；停用账号不入选；同 provider 重复内置渠道被阻止；核心依赖护栏通过。
- 风险／回滚：生命周期被统一抽象截断；先增适配不接默认入口，保持原存储可读且不双写凭据。

**U-04 公开模型映射与版本化能力目录**
- 候选文件：`internal/server/models_channels.go`、`models_flight.go`、`handler.go`、`internal/store/model.go` 及渠道映射接缝。
- 依赖：U-01、U-03 的适配描述；冻结返回字段后可与 RR 模块并行，handler.go 由单人负责。
- 最小范围：公开→真实映射、同名多渠道显式聚合、旧名兼容表、端点能力与来源；模型获取与快照读取分开。
- 验收：标准／内置同名共同供给；不同真实模型未显式映射不合并；image_generation 保留；刷新计数明细同版本，失败保留旧快照。
- 风险／回滚：名称碰撞及 SQL/内存不同步；映射歧义拒绝发布，旧目录保持可读，不用删用户映射纠正刷新。

阶段 B 门禁：两类渠道及模型能力可通过同一契约表达，内置生命周期不退化；尚不切换生产请求链。

### 阶段 C：纯 RR 与内部凭据执行

**U-05 渠道 RR 与请求尝试账本**
- 候选文件：`internal/channelroute/route.go`、`internal/server/channels_forward.go`、`channels_uniform_test.go`；新增窄选择器须先确认位置。
- 依赖：U-01、U-03；U-04 的协议能力契约；去除 weight 选路含义，不只隐藏 UI。
- 最小范围：候选并集去重、原子 RR、请求排除集及总尝试预算；priority/weight 存量值仅兼容读取、不参与选择。
- 验收：A/B/C/A 确定序列，重叠组不增加权重；禁用跳过、动态增删和并发原子性符合 F-02/F-04，不用随机统计证明轮询。
- 风险／回滚：共享游标竞态、重试重新初始化；先在 fake 路由验证，旧策略只留切换前回退，不允许新架构上线仍暗用随机权重。

**U-06 内部 Key／账号 RR 与执行反馈**
- 候选文件：`internal/pool/`、`internal/server/channels_forward.go`、gateway 反馈接缝及 Key 选择实现；与 U-05 共用文件串行交接。
- 依赖：U-03、U-05 的预算和排除集契约；生命周期状态不由选择器重新定义。
- 最小范围：每渠道内部 RR，跳过 disabled/cooling/unavailable，错误反馈更新原资源状态；下一渠道和内部资源都消耗同一请求预算。
- 验收：内部 a/b/c 序列；失败跨渠道／回到渠道取未尝试凭据；同账号即使有多个名称也不重复；取消、次数上限、SSE 已输出均停止重放。
- 风险／回滚：账号资格、并发预约和续期锁冲突；用假时钟及受控执行器验证，不通过真实上游试错。

阶段 C 门禁：两层 RR 及失败执行矩阵通过，适配不隐含另一套账号偏好；现有必要冷却／续期判断继续有效。

- 风险／回滚：旧客户端字段与代理误配；明确版本及错误，不能以重新暴露明文或把有限零额当无限来回滚。

### 阶段 E：存量迁移与兼容切换

**U-09 来源映射、权限钉住与幂等迁移**
