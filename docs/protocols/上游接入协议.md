## ① 术语与边界

### 1.1 什么叫"上游"

**上游 = 一个消费 `internal/gateway` 契约、因而被架构测试自动发现为"实现者"的包。**

判据（`internal/gateway/arch_test.go:102` 的 `discoverUpstreams`）：

```text
一个包是"上游实现" ⟺ 它的**非测试**依赖里含 internal/gateway
                     且不在 corePackages / discoveryExemptPackages 里
```

⚠ **不要再用历史上那三种登记方式**（`arch_test.go:268-287` 记着它们是怎么被绕过的）：

| 已废弃的判据 | 为什么废弃 |
|---|---|
| 人工维护 `knownUpstreams` 名单 | 忘登记即完全失效 |
| 磁盘推导 + "非上游白名单" | 把上游放进白名单目录即绕过 |
| 源码字面串（`gateway.Provider =`） | 用 import 别名即可绕过；还会自命中注释 |

⚠ `arch_test.go:45` 的 `upstreamPrefix` 是**遗留变量**，它自己的注释（`:42`）说"必须在此登记"，但那份说法已过期 —— 现行判据是包级依赖图，**加新上游不需要往任何名单里登记**（`AGENTS.md:387-389`）。

### 1.2 `gateway` 是接缝，不是上游

- `gateway` 定义契约（`Provider`/`Credential`/`Capability`/扩展点接口），**它自己不连任何上游**。
  守卫：`TestGatewayDoesNotDependOnAnyUpstream`（`arch_test.go:1004`）。
- 它同时在 `corePackages`（`arch_test.go:29-38`）里 —— 核心包**不得**依赖任何具体上游。
- 谁在核心包里写下某个上游的名字，就是耦合漏了（`provider.go:25` 原话）。

### 1.3 核心包清单（判据的"冻结面"）

```text
gateway / pool / logbuf / admin / server / scheduler / checkinlog / clientlogin
```
（`arch_test.go:29-38`。加新上游时这 8 个包**一行都不该改**。）

### 1.4 三条边界判据 + 可复制的检查命令

| 边界 | 守卫 | 现场命令 |
|---|---|---|
| 核心不得依赖具体上游 | `TestCoreDoesNotDependOnUpstreams` `arch_test.go:931` | `go test ./internal/gateway/ -run TestCoreDoesNotDependOnUpstreams -count=1` |
| 上游不得依赖核心业务包 / 不得互相依赖 | `TestUpstreamsDoNotDependOnCore` `arch_test.go:963` | `go test ./internal/gateway/ -run TestUpstreamsDoNotDependOnCore -count=1` |
| 被 ≥2 个上游依赖的包必须真的共享 | `TestSharedInfraIsGenuinelyShared` `arch_test.go:607` | `go test ./internal/gateway/ -run TestSharedInfraIsGenuinelyShared -count=1` |
| workbuddy 私有 SDK 不得被别家消费 | `TestPrivateSDKIsNotConsumedByOtherUpstreams` `arch_test.go:499` | `go test ./internal/gateway/ -run TestPrivateSDK -count=1` |

## ④ 诚实规则

1. **声明即承诺。** `Caps()` 里写了就必须真的能用（`capability.go:47`、`provider.go:46-48`）。
2. **少报是安全的，多报会被契约测试当场抓住。** 声明 `CapModels` 却返回空 ⇒ 红（`contract.go:126-131`）；
   声明不可验证能力位却 `AdminRoutes()` 返回 nil ⇒ 红（`contract.go:316-321`）；
   声明 `CapImport` 却没实现 `AccountImportExt` ⇒ 红（`capimport_guard_test.go:35`）。
3. **未实现的能力位不许出现在 `Caps()` 里。** 多报的代价不是"多余"，是**给前端画一个点了必然失败的按钮** ——
   `frontendchecklist` 意义上的死按钮，本项目明令禁止（`codar/codar.go:131-137` 的注释是这个原则的正面教材）。
4. **上游专属错误码只能由上游自己解释。** 反例判例：workbuddy 的裸数字 `12153` 曾被拿去判 codearts 的错误体，
   把健康账号永久禁用（`AGENTS.md:115-116`）。
5. **"暂时没有"要写在注释里，不要写成能力位。** phanthywork 刚接入时只声明 `CapChat|CapModels`，README 那行也明写
   "签到 / 额度探测本轮不做"（`README.md:86`）—— 它写的是"**本轮**不做"，所以同一轮补上 `checkin.go` / `quota.go` / `import.go`
   之后，能力位随之扩到 `CapChat|CapModels|CapQuotaProbe|CapCheckin|CapImport`（`phanthywork/provider.go:421-422`；2026-11-12 复扫校正）。
   **"本轮不做"是承诺不是免责**：`Caps()` 变了，README 那行必须同时改。
