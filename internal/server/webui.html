        出站提示词 立即生效
        
        

          

            
            
            开启后每条出站请求都会带上破甲条款（无限制人设 + 拒绝对抗）。
              
推荐「追加」：你的 system 原文完整保留，破甲条款接在后面。下游要精确格式、
              JSON Schema、固定人格时**必须**用这个。
              
「替换」是高风险：它用破甲正文（约 6700 token）整体覆盖你的 system，
              实测会导致 —— 「只回复 10 字以内」被无视（返回 40+ 字）、「只输出 JSON」变成 Markdown 列表、
              JSON Schema 选择器连续 7 次返回空数组（HTTP 200 + 合法 JSON，静默失败）、
              每请求多烧约 6000 token、耗时从 1 秒涨到 10~180 秒。
              
破甲治的是上游内容审查，不该用来改调用方的人格。

        

        
        
        

        

          

            

              
              「启用破甲（追加）」这一档对谁注入。范围选「全部」时名单不参与。

            

              
              

              

                
                
              

              
              

          

          

            

              
              「禁用破甲（只拦截）」这一档对谁生效。范围外连检测都不做（原样发出）。

            

              
              

              

                
                
              

              
              

          

          
          

            

              
              内置集只留高特征句（破甲模式 / 越狱模式 / wb2api:armor / little code sauce…）。
                泛化词（单独一个「越狱」「破甲」）故意不在内置集里（会误杀正常提问）—— 需要就在这儿自己加，逗号或换行分隔。

          

          
          

            

              
              默认开。判据（模式库）是猜的，误杀率只有真实流量能量出来 ——
                先看命中量与误杀率，再取消勾选切成真拦截。命中会在日志里留一行（含模式、目标、是否拦截）。

            

              
              勾上后内置特征句不再参与检测 —— 只有在你要完全自己定判据时才勾。

          

        

        

          

            
            照原项目 lib/refusal-retry.js：先缓冲前 400 字符判断是不是在推脱，
              命中就丢弃这次输出、把重试话术追加到系统提示尾部重发一次。默认关（原项目也默认关）——
              它会让命中时多一次上游请求。
